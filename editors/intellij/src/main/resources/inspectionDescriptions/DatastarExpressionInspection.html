Checks Datastar expressions with a JavaScript parser: syntax errors at the right column, unknown actions such as @Post with the right name as a quick fix, Datastar Pro actions (a hint: they need the Pro bundle), and a hyphen after a signal ($foo-bar, $count-1), which Datastar swallows into one signal name: the fix is the camelCase signal or the spaced subtraction. It also tells where Datastar's own rewrite of an expression does what JavaScript would not: a $name in the text of a template literal that also holds a ${...}, or inside a regular expression, is rewritten there too; a quote in a comment or a regular expression leaves a later $name as a JavaScript variable; and a ; inside brackets splits a value that is read, which loses it.
