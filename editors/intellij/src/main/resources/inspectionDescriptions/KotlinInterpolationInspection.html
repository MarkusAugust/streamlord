Reports a Kotlin value written into a Datastar expression or an HTML string, judged by where it lands, as interpolate(...) judges it at run time.

A string template where a Datastar signal was meant: "$count++" becomes "++" at runtime, and the browser never sees a signal. In a Datastar expression handed to the DSL this is an error; in a data-* expression of an HTML string, a warning, since a server value there works as often as it is the trap.

A value in element text or a quoted attribute, where escaping is enough, is a hint, or a warning for a String: build the string with interpolate(...), which escapes it. A value at the start of a URL, in style, in a Datastar expression, in a script or an event handler, or in an unquoted attribute value is a warning, since escaping does not help there. Constants, literals, numbers and booleans, and markup built in the template are left alone.

Quick fixes: the DSL helper (increment("count"), signal("count"), toggle("open")), a $$"..." literal (Kotlin 2.2+) where a single dollar is text, the ${'$'}count escape, or the literal rewritten as interpolate(...) with its import.
