Reports a Kotlin value written into a Datastar expression or an HTML string, judged by where it lands, as interpolate(...) judges it at run time.

A string template where a Datastar signal was meant: "$count++" becomes "++" at runtime, and the browser never sees a signal. In a Datastar expression handed to the DSL this is an error; in a data-* expression of an HTML string, a warning, since a server value there works as often as it is the trap.

Each value is judged by its Kotlin type. A value in element text or a quoted attribute, where escaping is enough, is a hint, or a warning for a String and for markup outside element text: build the string with interpolate(...), which escapes it. A value at the start of a URL, in style, in a Datastar expression, in a script or an event handler, or in an unquoted attribute value is a warning, since escaping does not help there.

Nothing is reported for the author's own values: constants, literals, an if or when between literals, an entry of a Kotlin enum that does not override toString, a call to a Streamlord helper such as signal("count") whose arguments are all of these, and markup in element text. A helper given any other value, signal(q), is judged by its type, since what it writes runs as code. A number or a boolean is safe where escaping is enough and in a Datastar expression, but where a signal could stand ("$count" with an Int count) it is a hint, since the signal may have been meant.

Where the module has Streamlord's core, a call to interpolate(...) is judged as it will run. A Kotlin template in its format is filled in before interpolate sees the markup, so it is neither escaped nor refused: a warning. More or fewer %s placeholders than values is an error, since interpolate then throws. A placeholder where interpolate refuses the value, a String in a Datastar expression or a Boolean in style, is an error; a value the text cannot tell there is a warning.

Quick fixes, each offered where the project can use what it writes. The DSL helper (increment("count"), signal("count"), toggle("open")) with its import, where the module has streamlord-html, no import from elsewhere takes the helper's name, and the helper says the whole literal. A $$"..." literal (Kotlin 2.2+) where a single dollar is text, and the ${'$'}count escape, in any project. The literal rewritten as interpolate(...) with its import, where the module has Streamlord's core and interpolate keeps every value in it: a trim call stays on the format, a $$"..." literal keeps its prefix, and literals joined with + become one. For a value that may be null, which a template writes as null and interpolate as nothing, it is offered and not put first. Where interpolate refuses one value, the message of each other value says which; CSS in the body of a <style> the rewrite passes as Trusted(...), from that value's own warning. The same rewrite is a context action anywhere in such a string. Quotes around an unquoted attribute value, and a template in a format made a %s placeholder with its value passed in its place. For a String in element text, which may be text from outside or markup you built, the rewrite is offered beside "Mark … as markup", which wraps the value in Trusted(...), again only with core, and neither comes first: which one is right only you know.

Without core no call is Streamlord's, and the message says what the browser does and what plain Kotlin or kotlinx.html can do about it, rather than send you to interpolate. A call, or a value whose type the IDE cannot tell, in element text is then a hint, since it may be markup you built; a String keeps its warning. A call that resolves to another library, such as the official Datastar SDK's patchElements, is not Streamlord's: the HTML string handed to it is judged as any other HTML string. While the IDE indexes it cannot tell what the module has or what a call resolves to: core counts as there, every call of a Streamlord name as Streamlord's, and the file's imports say whether the DSL is.
