The browser lowercases attribute names, so a capital letter in a key never reaches Datastar: data-signals:fooBar declares $foobar. The quick fix writes the kebab-case key that comes back as the intended name, with __case.camel where Datastar's default is not camel.

In the DSL the SDK writes a camelCase key correctly on its own; a hint on the call says what goes on the wire, so nothing is hidden.

A signal name in a DSL call holds no hyphen: Datastar's client reads one as a capital in an attribute key and as a hyphen in an expression or a patch, so dataSignals("foo-bar", ...) and signal("foo-bar") would name two signals, and the SDK refuses the name at runtime. The quick fix writes it in camelCase, fooBar. A key with a hyphen inside a value is data, and an expression reaches it with brackets: signal("form['first-name']").
