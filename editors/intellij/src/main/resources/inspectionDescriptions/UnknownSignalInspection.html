A signal that an expression reads but no file in the project defines: data-on:click="$telefon++" on a page whose data-signals:teller declares $teller. Datastar reads it as undefined and says nothing. When a defined name is close, the quick fix writes it.

A signal is defined by a data-signals, data-bind, data-ref, data-indicator, data-computed or data-match-media attribute, by the DSL calls that write one (dataSignals, patchSignals, signal and the rest), by a property of a @Serializable class, or by an assignment $name = ... in an expression. A signal the page gets from somewhere the project index does not read, a script or another repository, is reported too; suppress it there, or turn the inspection off.

The other direction is reported in a Kotlin file: a signal the server reads, through a property of a @Serializable class that readSignals reads into or a lookup such as signals.string("query"), that no page in the project declares. The handler gets the default, or null, and nobody is told. This is the signal-never-declared check that signalDrift runs in your own tests. A handler that patches a class, patchSignals(Form(...)), declares its properties as a page does.

The check sees the files of the project and nothing else. A signal set by a server patch whose class or keys the file does not write down, patchSignals(json) with a string built elsewhere, or declared by pages outside the project, a service opened alone whose pages are in another folder, is warned on though the browser has it. Open the folder that holds both, suppress the warning there, or turn the inspection off.
